## Upstream ProgramBench Facts

- Inference image: one `linux/amd64` cleanroom Docker image per task, tagged
  `task_cleanroom_v6`.
- Agent input: documentation plus `/workspace/executable`, with no internet.
- Submission format: `<run_dir>/<instance_id>/submission.tar.gz`.
- Evaluation: extract submission, run `./compile.sh`, require `./executable`,
  stash the candidate executable, inject hidden per-branch test blobs, and read
  JUnit XML.
- Primary score: after active-branch and ignored-test filtering from
  `tests.json`, score is `passed / total`. Missing expected tests are injected
  as `not_run` rather than silently ignored.
- Instance filters in the public code are intentionally simple:
  regex-by-instance-id, deterministic shuffle, slice, and `has_test_branch`.

## Paper-Level Oracle-Test Target

The paper describes ProgramBench oracle tests as behavioral pytest suites
generated by an agent that can inspect the source repository, existing tests,
and documentation, then probe the original executable. The generation loop
harvests existing behavioral tests, measures line coverage, iteratively adds
tests for uncovered code paths, flags weak assertions, discards tests that do
not deterministically pass the gold binary, and discards tests that pass a dummy
binary.

Our reproduction target is therefore not byte-identical tests. It is comparable
behavioral strength:

- pass the reference executable;
- reject dummy or trivial candidates;
- run deterministically and offline;
- avoid source leakage in agent-visible material;
- reach source coverage comparable to official ProgramBench tests and/or the
  upstream repo's native tests.
